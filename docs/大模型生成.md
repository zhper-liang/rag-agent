# 大模型生成

## 1. 目标

把 [Prompt 组装](Prompt%20组装.md) 产出的 `PromptPackage` 发给大模型，流式推给前端：
- 所有场景统一走 OpenAI 兼容接口，每个场景一个主模型、一个备用模型。
- 首个 token 之前出错可以重试或切备用模型；开始输出之后出错不重试，标记中断。
- 正文直接推模型原文，后处理不改正文，只在结束后追加一个 `final` 事件。
- 记录模型、用量、首字延迟、结束原因，交给后处理和监控。

输入：`PromptPackage`（scene、system、messages、version）。
输出（写入 RAGState）：`answer`（模型原文）、`gen_meta`（§9）。

参数在 `config.yaml` 的 `llm` 段：`endpoints` 定义接入点，`scenes` 定义每个场景用哪两个接入点。

## 2. 流程

```
PromptPackage
  ↓ 按 scene 选场景配置：rag / rag_empty → generate，chat → chat
  ↓ 依次尝试 primary、fallback：
  │    转成 LangChain 消息（当前接入点不支持图片时，图片块去掉，只留说明文字）
  │    流式调用，等首个非空 token（每次最多 first_token_timeout_s）
  │    首字前出错：按错误类型重试同一模型，或切到下一个接入点（§6）
  ↓ 拿到首个 token 后，边读边推 token 事件（strip_think 时先过滤思考内容）
  │    中途出错：停止，标记 interrupted，已生成的部分照常交给后处理
  ↓ 写回 answer、gen_meta → postprocess
```

## 3. 接入点与场景

接入点（`llm.endpoints.<name>`）：

| 字段 | 说明 |
|------|------|
| `base_url` / `model` | OpenAI 兼容接口地址和模型名 |
| `api_key_env` | key 所在的环境变量名；key 本身不写进 config.yaml |
| `vision` | 是否支持图片输入 |
| `structured_output` | 预处理、改写用哪种结构化输出：`function_calling` / `json_schema` / `json_mode` |
| `strip_think` | 模型会把思考过程写进正文（`<think>…</think>`）时打开 |
| `max_concurrency` | 本进程内同时发给这个接入点的请求数 |
| `extra_body` | 服务商特有参数，原样透传 |

场景（`llm.scenes.<name>`）：

| 场景 | 用在哪里 | 主要参数 |
|------|----------|----------|
| `generate` | rag、rag_empty 回答 | temperature 0.2，max_tokens 4096，首字前重试 + 切换 |
| `chat` | 闲聊 | temperature 0.5，max_tokens 512，首字前重试 + 切换 |
| `preprocess` | 意图、指代消解、查询扩展、范围识别 | temperature 0，超时 3 秒，不重试，失败切备用 |
| `rewrite` | 重试改写 | 同 preprocess |

启动时校验：`base_url`、`model` 不能为空；`api_key_env` 指向的环境变量必须存在；非本机地址必须是 https；场景引用的接入点必须存在。任何一项不满足就拒绝启动。

## 4. 客户端

用 langchain-openai 的 `ChatOpenAI`，每个接入点建一个实例并缓存：

```python
import os
from langchain_openai import ChatOpenAI

def build_client(ep, scene) -> ChatOpenAI:
    return ChatOpenAI(
        base_url=ep.base_url,
        api_key=os.environ[ep.api_key_env],
        model=ep.model,
        temperature=scene.temperature,
        max_tokens=getattr(scene, "max_tokens", None),
        timeout=getattr(scene, "total_timeout_s", None) or scene.timeout_s,
        max_retries=0,           # 关掉 SDK 自带重试，由 §6 统一控制
        stream_usage=True,       # 流式结束时带回用量（服务端不支持就估算）
        extra_body=ep.extra_body or None,
    )
```

## 5. 消息转换

```python
from langchain_core.messages import AIMessage, HumanMessage, SystemMessage

def to_messages(pkg, vision: bool) -> tuple[list, int]:
    """返回 (LangChain 消息, 因不支持图片而去掉的图片数)。"""
    out, dropped = [SystemMessage(pkg.system)], 0
    for m in pkg.messages:
        blocks = []
        for p in m.parts:
            if p.type == "text":
                blocks.append({"type": "text", "text": p.text})
            elif vision:
                blocks.append({"type": "image_url",
                               "image_url": {"url": f"data:{p.media_type};base64,{p.data_b64}"}})
            else:
                dropped += 1     # 图片说明文字已经在文本里，去掉图片块即可
        if not any(b["type"] == "image_url" for b in blocks):
            # 没有图片时传纯字符串：部分兼容服务不接受 list 形式的 content
            blocks = "".join(b["text"] for b in blocks)
        out.append((HumanMessage if m.role == "user" else AIMessage)(content=blocks))
    return out, dropped
```

- 切到不支持图片的备用模型时，图片自动降级为说明文字，`gen_meta.images_dropped` 记录去掉了几张。
- 历史消息本来就只有文本（Prompt 组装不重发历史图片）。

## 6. 重试与切换

### 6.1 generate / chat

错误分三类：

| 类型 | 例子 | 处理 |
|------|------|------|
| 可重试 | 429、5xx、连接错误 | 同一接入点按 `backoff_s` 退避重试，最多 `retries` 次，之后切下一个接入点 |
| 超时 | 等首个 token 超过 `first_token_timeout_s` | 不在同一接入点重试，直接切下一个接入点 |
| 不可重试 | 401、403、400（参数、上下文超长）、404 | 直接切下一个接入点 |

- 超时直接切换，是因为同一接入点卡住时重试大概率还是卡住；如果超时也重试 2 次，光主模型就会用掉 30 秒的总预算，备用模型没有机会。
- 首字前的总时长受 `pre_first_token_budget_s`（30 秒）限制，包括重试、退避和切换，超出就放弃并报错。
- 最坏情况：主模型超时 10 秒 → 备用模型超时 10 秒 → 报错，约 20 秒。
- 用了备用模型时 `gen_meta.fallback_used=true`，接入监控。

```python
import openai

def is_retryable(e: BaseException) -> bool:
    if isinstance(e, openai.APITimeoutError):
        return False                      # 超时按“切换”处理
    if isinstance(e, (openai.RateLimitError, openai.APIConnectionError,
                      openai.InternalServerError)):
        return True
    return isinstance(e, openai.APIStatusError) and e.status_code >= 500
```

### 6.2 preprocess / rewrite

接口：`structured_call(scene, eps, schema, messages)`（D-013 B），不追加可选参数。指标从进程全局入口读取；场景标签按图节点 preprocess/rewrite 或结构化模型 Preprocessed/Rewrite 识别，其余调用记为 eval，均为固定白名单。测试以 monkeypatch 替换全局指标或 build_client，不把客户端/指标传进函数。下面导入已测试实现。

- 不重试：主模型失败、超时（3 秒）或输出校验失败，直接用备用模型试一次，同样限 3 秒。
- 备用模型也失败，就按[用户问题预处理](用户问题预处理.md) §10 的规则降级，最坏多等 3 秒。

## 7. 流式调用

### 7.1 单次尝试

```python
import asyncio
from pydantic import BaseModel

class FirstTokenError(Exception):
    """首个可见 token 之前的失败：还没推给前端，可以重试或切换。"""
    def __init__(self, cause: BaseException, fatal: bool):
        super().__init__(repr(cause))
        self.cause, self.fatal = cause, fatal     # fatal=True：不在同一接入点重试

class GenerationFailed(Exception):
    pass

class StreamResult(BaseModel):
    text: str
    finish_reason: str | None
    usage: dict | None
    ttft_ms: int | None         # 只有 think.flush() 吐出可见内容时可能为 None
    interrupted: bool = False
    error: str | None = None
```

- 超时只管到“收到第一段原始内容”为止；打开 `strip_think` 时，模型在思考阶段也算已经有输出，不会被误判超时。
- 能不能重试，看有没有东西推给前端：只要还没推出去，出错都可以重试或切换，不会出现重复的正文。

```python
async def stream_once(client, messages, first_token_timeout: float, emit, think=None) -> StreamResult:
    loop = asyncio.get_running_loop()
    t0 = loop.time()
    it = client.astream(messages).__aiter__()
    parts, usage, finish, ttft = [], None, None, None
    raw_started = False
    try:
        while True:
            try:
                if raw_started:
                    chunk = await it.__anext__()
                else:   # 只对“第一段原始内容”计时
                    chunk = await asyncio.wait_for(it.__anext__(), first_token_timeout)
            except StopAsyncIteration:
                break
            usage = chunk.usage_metadata or usage
            finish = chunk.response_metadata.get("finish_reason") or finish
            raw = chunk.content if isinstance(chunk.content, str) else ""
            if not raw:
                continue
            raw_started = True
            text = think.feed(raw) if think else raw
            if text:
                if ttft is None:
                    ttft = int((loop.time() - t0) * 1000)
                parts.append(text)
                emit({"type": "token", "text": text})
        if think and (tail := think.flush()):
            parts.append(tail)
            emit({"type": "token", "text": tail})
    except Exception as e:
        if not parts:        # 还没推给前端：交给上层重试或切换
            fatal = isinstance(e, TimeoutError) or not is_retryable(e)
            raise FirstTokenError(e, fatal) from e
        return StreamResult(text="".join(parts), finish_reason=finish, usage=usage,
                            ttft_ms=ttft, interrupted=True, error=repr(e))
    if not parts:            # 正常结束但没有任何正文
        raise FirstTokenError(RuntimeError("empty response"), fatal=True)
    return StreamResult(text="".join(parts), finish_reason=finish, usage=usage, ttft_ms=ttft)
```

- 已经推出一部分后出错：不重试，返回 `interrupted=True`，已生成的部分照常交给后处理。
- `first_token_timeout` 只管第一段原始内容；之后读卡住由 httpx 的读超时（客户端 `timeout`）兜底，抛出后同样按中断处理。

### 7.2 过滤思考内容（strip_think）

`<think>` 标签可能被切在两个 chunk 之间，所以要缓冲可能是标签开头的尾部字符：

```python
class ThinkFilter:
    OPEN, CLOSE = "<think>", "</think>"

    def __init__(self):
        self.buf, self.inside = "", False

    def feed(self, s: str) -> str:
        self.buf += s
        out = []
        while True:
            tag = self.CLOSE if self.inside else self.OPEN
            i = self.buf.find(tag)
            if i >= 0:
                if not self.inside:
                    out.append(self.buf[:i])
                self.buf, self.inside = self.buf[i + len(tag):], not self.inside
                continue
            # 保留可能是标签前缀的尾部，其余部分可以确定处理
            keep = next((k for k in range(min(len(tag) - 1, len(self.buf)), 0, -1)
                         if tag.startswith(self.buf[-k:])), 0)
            ready, self.buf = self.buf[:len(self.buf) - keep], self.buf[len(self.buf) - keep:]
            if not self.inside:
                out.append(ready)
            return "".join(out)

    def flush(self) -> str:
        tail, self.buf = ("" if self.inside else self.buf), ""
        return tail
```

- 思考内容不推给前端，也不写进 `answer`。
- 服务商把思考过程放在单独字段（如 `reasoning_content`）时，LangChain 不会把它放进 `content`，不需要额外处理。

### 7.3 重试、切换与并发

接口：`stream_answer(pkg, scene, eps, sems, emit)`（D-013 B），不追加可选客户端/场景参数。内部 build_client 按接入点和场景配置缓存，每个事件循环独立，显式拥有同步/异步 HTTPX 连接；测试用 monkeypatch 替换 build_client，关闭后不得跨循环复用连接。完整实现负责首原始内容与可见正文预算、重试/切换、并发名额及取消清理，下面导入已测试实现。

```python
from ragagent.llm.stream import stream_answer
```

- `sems` 是每个接入点一个 `asyncio.Semaphore(max_concurrency)`，按进程计；多 worker 部署时实际并发是 worker 数 × 该值。
- 信号量覆盖整次生成（不只是首字前），这样才能真正限制同时在跑的请求数。

## 8. 流式输出（SSE）

入口为 `POST /api/chat`，响应 `text/event-stream`。请求 JSON 含 `question`、可选 `session_id`、`filters` 和 `use_scope`（严格布尔，默认 true，见[用户问题预处理](用户问题预处理.md) §8.3）；会话也可取 `X-Session-ID`，同传必须一致。会话标识必须为 1～128 位 ASCII 字母、数字、下划线或连字符，同会话串行执行，checkpoint 按该标识隔离。问题非空且不得超过 `preprocess.max_question_chars`，过滤字段按预处理契约验证；不接受额外 JSON 字段。

`meta.attachments` 和 `final.sources[].images` 在 API 层去掉内部 `image_path`，增加公开 `url`，路由为 `GET /api/images/{doc_id}/v{version}/{filename}`。只有合法 `clean/{doc_id}/v{version}/images/{filename}` 可映射；非法路径的 `url` 为 `null`，不向前端暴露本地路径。URL 不代表文件存在，图片路由还会核验登记状态、版本和路径边界，详见[后处理](后处理.md) §7。

| 事件 | 发出位置 | 内容 |
|------|----------|------|
| `progress` | preprocess / retrieve / rerank / build_context / generate 节点 | 阶段提示：“正在理解问题…”“正在检索…”“正在整理资料…”“正在生成…” |
| `meta` | build_context 节点 | `scope_note`、`scoped`（本次检索是否带软过滤，前端据此显示“取消限定”）、附件图片（路径换成前端可访问的 URL） |
| `token` | generate 节点 | 正文增量（模型原文，已过滤思考内容） |
| `final` | postprocess 节点 | 引用校验结果、来源列表、截断 / 中断标记（见[后处理](后处理.md)） |
| `error` | 任意节点 | 面向用户的错误提示，不含内部细节 |

- 各节点按 D-003 A 接收 `runtime: Runtime[Deps]`，通过 `runtime.stream_writer` 推自定义事件（`deps.write` 仅作可选测试覆盖），API 层用 `graph.astream(..., stream_mode=["custom", "updates"])` 读出来，把 `custom` 事件转成 SSE。
- fallback、clarify 这类不调用 LLM 的回答，整段作为一个 `token` 事件推送，后面照常跟 `final`。
- 客户端断开时取消整个图的执行，正在进行的 LLM 请求随之取消，不再继续计费。

```python
from langgraph.config import get_stream_writer

from langgraph.runtime import Runtime
from ragagent.graph.deps import Deps

async def generate_node(state: RAGState, runtime: Runtime[Deps]) -> dict:
    deps = runtime.context
    cfg, SEMS = deps.cfg, deps.sems
    emit = deps.write or runtime.stream_writer
    pkg = assemble(state, cfg, count=deps.count, env=deps.prompt_env)
    scene = cfg.llm.scenes.generate if pkg.scene != "chat" else cfg.llm.scenes.chat
    emit({"type": "progress", "stage": "generating"})
    try:
        res, info = await stream_answer(pkg, scene, cfg.llm.endpoints, SEMS, emit)
    except GenerationFailed as e:
        log.error("generate failed_type=%s", type(e).__name__)
        emit({"type": "error", "message": "回答服务暂时不可用，请稍后再试"})
        return {"answer": "", "gen_meta": {"status": "failed", "prompt_version": pkg.version}}
    return {"answer": res.text, "gen_meta": build_gen_meta(pkg, res, info)}
```

generate 之后固定进入 postprocess；`status=failed` 时后处理不保存这一轮到对话历史。

## 9. gen_meta

| 字段 | 说明 |
|------|------|
| `status` | `ok` / `truncated`（finish_reason=length）/ `interrupted`（中途出错）/ `failed` |
| `endpoint` / `model` / `fallback_used` / `attempts` | 实际用的接入点、模型，是否用了备用，每次失败的记录 |
| `prompt_version` / `est_input_tokens` | 来自 PromptPackage |
| `finish_reason` | 模型返回的结束原因 |
| `usage` / `usage_estimated` | 输入、输出 token 数；服务端没返回时用本地 tokenizer 估算，并标记 `usage_estimated=true` |
| `ttft_ms` / `total_ms` | 首个可见 token 的延迟、总耗时 |
| `images_dropped` | 因接入点不支持图片而去掉的图片数 |

后处理根据 `status` 决定是否在 `final` 里提示“回答过长已截断”或“回答中断”。

## 10. 日志与安全

- 记录：接入点、模型、prompt 版本、`gen_meta` 全部字段、用到的 chunk_ids。
- 不记录完整 Prompt 和回答原文（里面有资料内容）。调试时按 `logging.prompt_sample_rate` 抽样记录，默认 0，抽样日志同样遵守 `logging.retain_days`。
- trace 上报到 Langfuse 云端，默认遮掉所有原文只留元数据，见[评估与监控](评估与监控.md) §9。
- key 只从环境变量读，不进日志；错误信息只记异常类型和状态码。
- 资料原文和图片会发给配置的接入点。选接入点时要确认服务商的数据处理条款；敏感资料可以把 `base_url` 指向内网部署的兼容服务（如 vLLM），配置不用改结构。
- 非本机地址必须是 https（启动时校验）。

## 11. 延迟（未实测）

| 阶段 | 估算 |
|------|------|
| 预处理 | 0.5~1 s（主模型失败切备用时最多约 6 s） |
| 检索 + 重排 + 上下文构造 | 约 1.5 s |
| 生成首字 | 1~2 s，取决于接入点 |
| 首字总延迟 | 约 3~4.5 s，期间前端显示 progress 事件 |
| 首字前最坏情况 | 主、备各超时 10 s，约 20 s 后报错 |

## 12. 验证

用假的流式模型（按脚本返回 chunk 或抛异常）做单元测试：
- 正常流式：token 按顺序推出，`answer` 等于所有 token 拼接。
- 429 一次后成功：同一接入点重试，`attempts` 有 1 条记录，`fallback_used=false`。
- 首字超时：不在同一接入点重试，直接切备用。
- 401 / 400：直接切备用。
- 主备都失败：抛 `GenerationFailed`，前端收到 `error` 事件。
- 中途出错：不重试、不重复推 token，`status=interrupted`。
- 思考标签被切在 chunk 边界上时能正确过滤；只有思考内容时不会被误判为首字超时。
- 接入点 `vision=false` 时图片块被去掉，`images_dropped` 正确。
- 启动校验：缺 base_url / model / 环境变量、非本机 http 地址都拒绝启动。

联调：拿到真实接入点后，用同一批问题分别测主、备模型的首字延迟、finish_reason 和 usage 的返回格式。

## 14. 待讨论

- 四个接入点的 `base_url`、`model` 和 key 等你提供；key 放环境变量或不提交的 `.env`。
- 备用模型的上下文长度要能放下约 12k 输入 + 2k 输出，否则切过去会直接报 400。
- 主模型是否支持图片，决定 `main.vision` 的取值。
- 不同兼容服务返回的 finish_reason、usage、错误码可能不一致，拿到接入点后要联调确认。
- `structured_call`（§6.2）：tool 参数不是合法 JSON 时，langchain-openai 1.6.6 的 `with_structured_output(method="function_calling")` 不抛异常，`ainvoke` 直接返回 None，已按 D-005 A 将 None 当失败切备用；字段不符时抛校验异常（P0 桩的 `test_llm_structured_bad_output` 固定了这两种行为）。用户已裁决选 A，不使用 `include_raw=True`；主备各试一次，备用仍失败就按规则降级。
