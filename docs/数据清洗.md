# 数据清洗

## 1. 目标

把 PDF、Word、PPT、图片、Markdown/TXT 统一转成 Markdown 和结构化的 Block 序列，去掉噪声，保留标题层级、表格、公式和图片，供[文档切分](文档切分.md)使用。

图片不只保留 OCR 文字，原图也保留下来。向量化使用 Visualized-BGE（bge-m3 底座），可以把图片和文字编码到同一个向量空间，用户用文字提问时也能检索到相关图片。

- 输入：原始文件目录
- 输出：每个文件一份 `full.md`、一份 `clean.json`（CleanDocument）、图片目录，以及 SQLite 登记记录

## 2. 格式路由

| 格式 | 处理方式 | 说明 |
|------|----------|------|
| PDF | MinerU API | 文字版和扫描版都交给 MinerU，由它判断是否需要 OCR |
| DOC / DOCX | MinerU API | 旧格式 .doc 不用自己转换 |
| PPT / PPTX | MinerU API | 每页幻灯片对应一个页码 |
| PNG / JPG / JPEG | MinerU API + 保留原图 | OCR 出的文字和原图都进入后续流程 |
| MD / TXT | 本地解析 | 本来就是文本，不需要走 MinerU |

当前版本不支持 Excel（xlsx / xls），扫描时跳过并记录日志。

路由写在 `config.yaml` 的 `ingest.parse_routes` 里，某种格式要换解析器只改配置即可。本文其余参数（MinerU、清洗、图片、质量过滤、去重）也都在 `ingest` 段，默认值以该文件为准。

## 3. 流程

```
扫描文件 → 计算 sha256，对比登记表 → 没有变化则跳过
   ↓ 新增或变更
按后缀路由 ─┬─ MinerU：申请上传地址 → 上传 → 轮询 → 下载 zip → 解压
           │           （full.md + content_list.json + images/）
           ├─ MD/TXT：直接读取
           └─ 其他（含 Excel）：跳过，记录日志
   ↓
转成 Block 序列 → 清洗规则 → 图片处理 → 质量过滤 → 去重
   ↓
写出 clean.json 和 full.md，更新登记表
```

## 4. MinerU 接入

### 4.1 部署方式

| 方式 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 官方云 API（mineru.net） | 不需要 GPU，接入快 | 文档要上传到第三方；有单文件大小、页数和每日额度限制 | 公开资料、原型阶段 |
| 自部署（`mineru-api` / sglang 后端） | 数据不出内网，没有额度限制 | 需要 GPU，要自己维护 | 敏感文档、正式环境 |

两种方式都通过同一个 `MinerUClient` 接口调用。先用云 API 跑通，敏感数据再切到自部署。

### 4.2 云 API 调用流程（批量上传本地文件）

```
1. POST /api/v4/file-urls/batch
   请求体：files（文件名 + data_id）+ 解析参数
   返回：batch_id，以及每个文件的上传地址 file_urls
2. PUT 把文件上传到对应的 file_url（上传完成后自动开始解析）
3. GET /api/v4/extract-results/batch/{batch_id}
   轮询 extract_result[].state：waiting-file / pending / running / converting / done / failed
4. state=done 时，下载 full_zip_url，解压到 data/parsed/{doc_id}/v{version}/
```

鉴权方式为 `Authorization: Bearer <MINERU_TOKEN>`，token 放在环境变量里，不写进代码或配置文件。

> 以上接口路径、字段和限制是我根据目前了解整理的，写代码前要以 MinerU 官方文档为准。

### 4.3 解析参数

| 参数 | 取值 | 说明 |
|------|------|------|
| `model_version` | `vlm`（默认）/ `pipeline` | vlm 精度更高；pipeline 速度更快。选型时拿样本对比 |
| `is_ocr` | `false` | 扫描页由 MinerU 自动识别；全是扫描件时可以设为 `true` |
| `enable_formula` | `true` | 公式输出为 LaTeX |
| `enable_table` | `true` | 表格输出为 HTML |
| `language` | `ch` | 中英混排也用 ch |
| `data_id` | `doc_id` | 回填到结果里，用于和登记表对应 |
| `page_ranges` | 按需设置 | 超大文件分段解析时使用 |

### 4.4 解析产物

```
data/parsed/{doc_id}/v{version}/
├── full.md                 # 完整 Markdown，给人看、调试用
├── *_content_list.json     # 按阅读顺序排列的内容块（带类型、页码、标题层级）→ 转 Block 的主要输入
├── images/                 # 裁出来的图片、表格截图、公式截图
├── layout.json             # 版面分析的中间结果，排查问题用
└── *_origin.pdf            # 转换后的 PDF（Office 文件和图片输入时会有）
```

用 `content_list.json` 而不是 `full.md` 转 Block，因为它自带 `page_idx` 和块类型，不用再解析 Markdown，引用定位也更准。

### 4.5 客户端骨架（草稿）

```python
import asyncio, os, zipfile
from pathlib import Path
import httpx
from pydantic import BaseModel

BASE = "https://mineru.net/api/v4"

class ParseJob(BaseModel):
    doc_id: str      # 16 位 hex，可安全用作目录名
    path: Path
    out_dir: Path    # data/parsed/{doc_id}/v{version}

class MinerUClient:
    def __init__(self, token: str | None = None, model_version: str = "vlm"):
        token = token or os.environ["MINERU_TOKEN"]
        self.http = httpx.AsyncClient(
            headers={"Authorization": f"Bearer {token}"}, timeout=60)
        # 上传地址是预签名 URL，不能带鉴权头，否则签名校验会失败
        self.upload = httpx.AsyncClient(timeout=300)
        self.model_version = model_version

    async def parse_batch(self, jobs: list[ParseJob],
                          poll_interval: float = 5, timeout: float = 1800
                          ) -> dict[str, Path | Exception]:
        """提交一批文件，返回 doc_id -> 解压目录 或 异常。"""
        resp = await self.http.post(f"{BASE}/file-urls/batch", json={
            "files": [{"name": j.path.name, "data_id": j.doc_id} for j in jobs],
            "model_version": self.model_version,
            "enable_formula": True, "enable_table": True, "language": "ch",
        })
        resp.raise_for_status()
        data = resp.json()["data"]
        for job, url in zip(jobs, data["file_urls"]):
            with job.path.open("rb") as f:
                (await self.upload.put(url, content=f.read())).raise_for_status()
        return await self._poll(data["batch_id"], jobs, poll_interval, timeout)
```

轮询、下载、安全解压：

```python
    async def _poll(self, batch_id, jobs, interval, timeout):
        by_id = {j.doc_id: j for j in jobs}
        results: dict[str, Path | Exception] = {}
        loop = asyncio.get_running_loop()
        deadline = loop.time() + timeout
        while len(results) < len(jobs) and loop.time() < deadline:
            await asyncio.sleep(interval)
            resp = await self.http.get(f"{BASE}/extract-results/batch/{batch_id}")
            resp.raise_for_status()
            for item in resp.json()["data"]["extract_result"]:
                doc_id = item.get("data_id")
                if doc_id not in by_id or doc_id in results:
                    continue
                if item["state"] == "done":
                    try:
                        results[doc_id] = await self._fetch(
                            item["full_zip_url"], by_id[doc_id].out_dir)
                    except Exception as e:
                        results[doc_id] = e
                elif item["state"] == "failed":
                    results[doc_id] = RuntimeError(item.get("err_msg", "failed"))
        for doc_id in by_id.keys() - results.keys():
            results[doc_id] = TimeoutError(f"batch {batch_id} 超时")
        return results

    async def _fetch(self, url: str, out_dir: Path) -> Path:
        out_dir.mkdir(parents=True, exist_ok=True)
        zip_path = out_dir / "result.zip"
        async with self.upload.stream("GET", url) as r:
            r.raise_for_status()
            with zip_path.open("wb") as f:
                async for chunk in r.aiter_bytes():
                    f.write(chunk)
        root = out_dir.resolve()
        with zipfile.ZipFile(zip_path) as zf:
            for name in zf.namelist():  # 防止 zip 路径穿越
                if not (root / name).resolve().is_relative_to(root):
                    raise ValueError(f"非法路径: {name}")
            zf.extractall(root)
        zip_path.unlink()
        return root
```

### 4.6 容错与限额

- 分批：每批文件数不超过 API 上限（按官方文档配置，默认 50）。
- 大文件：超过页数或大小限制的 PDF，用 PyMuPDF 按页拆成多段分别提交，解析后按 `page_idx` 偏移合并。Office 文件太大时，先用 LibreOffice 转成 PDF 再拆分。
- 重试：网络错误和 5xx 按指数退避重试 3 次；`failed` 状态记入登记表，下次运行时重新提交。
- 并发：用 `asyncio.Semaphore` 限制同时进行的批次数，避免触发限流。
- 额度：遇到额度用完的错误码就停止提交，剩下的文件保持 `pending`，第二天继续。
- 幂等：`parsed/{doc_id}/v{version}/` 已经存在且完整时，直接复用，不重新解析。

## 5. 本地解析（MD / TXT）

- MD：用 markdown-it-py 解析成 Block。本地引用的图片复制到 `images/`，生成 image Block。
- TXT：按空行分段，没有标题信息。

## 6. 中间格式

```python
from typing import Literal
from pydantic import BaseModel, Field

BlockType = Literal["heading", "paragraph", "table", "list",
                    "code", "equation", "image"]
DOC_ID_PATTERN = r"^[0-9a-f]{16}$"

class Block(BaseModel):
    type: BlockType
    text: str                      # table 用 Markdown；equation 用 LaTeX；image 用说明文字
    level: int = 0                 # heading 的层级 1~6
    page: int | None = None        # 页码（1 起），PPT 为幻灯片序号
    image_path: str | None = None  # image / table 截图的相对路径
    meta: dict = Field(default_factory=dict)  # caption、footnote、上下文等

class CleanDocument(BaseModel):
    doc_id: str = Field(pattern=DOC_ID_PATTERN)  # sha1(相对路径)[:16]，版本之间保持不变
    version: int
    source_path: str
    file_type: str       # pdf / docx / pptx / png / md / ...
    parser: str          # mineru-vlm / mineru-pipeline / text
    title: str
    content_hash: str    # 原文件 sha256
    blocks: list[Block]
    meta: dict = Field(default_factory=dict)
```

跨模块传递的数据结构统一用 pydantic v2 的 `BaseModel`，字段和这里逐字对应 `src/ragagent/ingest/models.py`。构造时一律用关键字参数。

## 7. content_list → Block 映射

| content_list `type` | 条件 | Block |
|---------------------|------|-------|
| `text` | 有 `text_level` | heading，`level=text_level` |
| `text` | 没有 `text_level` | paragraph |
| `list` | | list |
| `table` | | table：`table_body`（HTML）转 Markdown；`table_caption` / `table_footnote` 放进 meta；`img_path` 保留 |
| `image` | | image：`img_path`；caption（`image_caption` 或 `img_caption`）用作 text |
| `equation` | | equation：LaTeX 文本 |
| `code` | | code |
| 其他 | | 记录警告，按 paragraph 处理 |

- `page_idx` 从 0 开始，存入 `Block.page` 时加 1。
- 不同 MinerU 版本字段名有差异，映射时两种写法都要兼容，遇到不认识的字段记录日志，不要直接报错。
- HTML 表格转 Markdown 时，先展开 `rowspan` / `colspan`。表格太复杂时（嵌套表格，或展开后超过 20 列），保留 HTML 原文，并在 meta 中标记 `format=html`。

## 8. 清洗规则

MinerU 已经处理了大部分页眉页脚、页码和断行，这里补充处理它没覆盖或处理不稳定的情况。每条规则是一个 `list[Block] -> list[Block]` 函数，可以单独开关和测试。

1. 编码与空白：NFKC 归一化，去掉零宽字符和控制字符，合并连续空白，去掉中文字符之间多余的空格。
2. 标题层级修正：MinerU 给出的标题层级经常不可靠（常见情况是全部为 1 级），按编号重建：

   | 编号模式 | 层级 |
   |----------|------|
   | `第X章` / `第X部分` | 1 |
   | `第X节` / `一、` | 2 |
   | `1.` / `1.1` / `1.1.1` | 点号数量 + 1（`1.` 按 1 级处理） |
   | `（一）` / `(1)` | 当前层级 + 1 |
   | 无编号 | 保留 MinerU 给出的层级 |

   另外，超过 50 字、以句号结尾的“标题”降级为 paragraph；整段包裹标题的 Markdown 强调标记（`**…**`、`__…__`、`*…*`）先去掉，否则会进入标题路径和文档标题。
3. 残留页眉页脚：同一段短文本在超过 50% 的页面重复出现时删除。
4. 目录页：大量“标题……页码”格式的行判定为目录页，删除。
5. 跨页表格合并：相邻页的两个表格列数相同，且后一个没有表头或表头与前一个相同，就合并成一个。
6. 公式：保留 LaTeX 原文，检查括号是否配对，不配对时在 meta 中标记 `latex_invalid`。
7. PPT：每页幻灯片的标题作为 2 级 heading，文件名作为 1 级。
8. 噪声：删除配置里列出的水印文本、只有符号的行、单独一行的页码。

## 9. 图片处理

Visualized-BGE 可以对“图片 + 文字”一起编码，所以图片按独立的检索单元保留，而不是只保留 OCR 文字。

### 9.1 过滤

| 规则 | 处理 |
|------|------|
| 短边小于 64px，或面积小于 10000 像素 | 丢弃（图标、项目符号） |
| 同一张图（感知哈希 pHash 相同）在超过 30% 的页面出现 | 丢弃（logo、页眉装饰图） |
| 近似纯色或空白（像素标准差很小） | 丢弃 |

### 9.2 补充上下文

图片单独编码时语义信息少，需要给它配上文字：
- 优先用 caption；
- 没有 caption 时，取图片前后各一个 paragraph（每个截取 200 字以内）；
- 结果存到 `meta.context`，向量化时和图片一起编码。

### 9.3 各类图片的处理

- 独立图片文件：MinerU 的 OCR 文字生成 paragraph Block，原图额外生成一个 image Block，`image_path` 指向原文件的副本。
- 表格截图：表格文字已经在 table Block 里了，截图只保留路径，前端展示用，不单独向量化。
- 公式截图：同上，不单独向量化。
- 图表（流程图、柱状图等）：可选接入多模态 LLM 生成文字描述，存到 `meta.description`。成本较高，默认关闭。

原图保存在 `images/` 目录，不做压缩，缩放由向量化阶段的模型预处理完成。

## 10. 质量过滤

| 规则 | 处理 |
|------|------|
| Block 文本少于 5 个字符（heading 和 image 除外） | 丢弃 |
| 乱码比例高（非 CJK/字母/数字/常用标点的字符超过 30%） | 丢弃并记录日志 |
| 整篇文档有效字符少于 50，且没有保留下来的图片 | 整篇丢弃，登记表标记为 `empty` |

阈值写在配置里，先用上面的初始值，之后根据抽样结果调整。

## 11. 去重

- 文件级：原文件 sha256 相同时只保留一份，其余在登记表中记录 `duplicate_of`。
- 文档级：对清洗后的全文计算 MinHash（datasketch，Jaccard 阈值 0.9），命中时同样记录 `duplicate_of`，不入库。常见情况是同一份内容的 PDF 版和 Word 版。
- 图片级：同一文档内 pHash 相同的图片只保留第一张。
- chunk 级去重放到[文档切分](文档切分.md)之后。

## 12. 增量处理与登记表

SQLite 表 `documents`：

| 字段 | 说明 |
|------|------|
| doc_id | 主键，sha1(相对路径)[:16] |
| source_path | 文件路径 |
| title | 文档标题：取第一个 1 级标题，没有就用文件名（去扩展名）；用于从问题里识别文档范围 |
| file_type / parser | 文件类型 / 使用的解析器 |
| content_hash | 原文件 sha256 |
| version | 每次内容变化加 1 |
| status | `pending` / `parsing` / `cleaned` / `indexed` / `empty` / `duplicate` / `unsupported` / `failed` / `deleted` |
| mineru_batch_id | 便于排查问题和重新拉取结果 |
| pages | 页数 |
| duplicate_of | 重复时指向保留的那份 doc_id |
| error | 失败原因 |
| updated_at | 更新时间 |

- 哈希没变：跳过。
- 哈希变了：version + 1，重新解析；下游按 doc_id 删除旧 chunk，再写入新的。
- 文件已删除：状态改为 `deleted`，下游删除对应向量。
- 中断恢复：`parsing` 状态且有 batch_id 的文件，重启后优先重新拉取结果，不重新提交。
- 单个文件失败不影响整批。

## 13. 存储布局

```
data/
├── raw/                              # 原始文件（只读）
├── parsed/{doc_id}/v{version}/       # MinerU 原始产物
├── clean/{doc_id}/v{version}/
│   ├── clean.json                    # CleanDocument
│   ├── full.md                       # 清洗后的 Markdown
│   └── images/                       # 过滤后的图片（检索结果展示和向量化都用这里的图）
└── registry.db
```

每个文档只保留最近 2 个版本，更早的定期清理。

## 14. 与向量化的衔接

- Visualized-BGE 输出 1024 维稠密向量，文本 chunk 和图片 chunk 都存在同一个向量字段里。
- 据我了解它不输出稀疏向量，所以关键词检索改用 Milvus 2.5+ 内置的 BM25（全文检索 Function，配中文分词器），具体放在[向量化建库](向量化建库.md)里写。
- 清洗阶段要保证：图片路径能访问到、`text` 字段干净（稠密向量和 BM25 都基于它加上标题路径）、页码准确（用于引用定位）。

## 16. 验证方式

- 每种格式准备 2~3 个样例放在 `tests/fixtures/`，同时保存 MinerU 的返回结果（content_list.json），测试时不用调用 API。
- `convert.py` 和每条清洗规则都写单元测试，对结果做快照比对。
- 选型测试：挑 10 份典型文档，分别用 `vlm` 和 `pipeline` 解析，人工比较表格、标题和公式的效果。
- 每批入库后抽样 20 份人工检查，统计丢弃率、失败率和每页平均耗时。

## 17. 待讨论

- 文档敏感程度：能不能上传到 MinerU 云端？
- 云端额度：按 1000 万 chunk 估算，大约是几百万页的量级，很可能超出云端每日额度。如果不够，要在 RTX 4060 上自部署 MinerU，并和向量化错开时间使用 GPU。
- 图表类图片要不要用多模态 LLM 生成描述（会增加成本和耗时）。
