# RAG 问答系统总揽（LangGraph + DiskANN）

## 1. 目标

构建一个可扩展的 RAG 问答框架：
- 编排层：LangGraph，把在线问答流程建模为有状态图（StateGraph），支持条件分支、重试、多轮对话。
- 检索层：Milvus 的 DISKANN 索引（基于磁盘的 Vamana 图索引），内存受限时也能支撑千万到亿级向量检索；同时用 Milvus 的标量过滤和 BM25 全文检索做混合检索。
- 模块化：每个环节独立成模块，可替换（Embedding 模型、LLM、重排器等）。

## 2. 整体流程

```
离线链路（建库）
  原始文档(PDF/Word/PPT/图片 → MinerU API；MD/TXT → 本地解析)
          → 数据清洗 → 文档切分 → 向量化(Visualized-BGE 图文稠密向量)
          → 写入 Milvus（DISKANN 稠密索引 + BM25 全文索引 + 标量字段）

在线链路（LangGraph 图）
  用户问题 → 问题预处理 → 混合检索(Milvus) → 重排 → 上下文构造
          → Prompt 组装 → 大模型生成 → 后处理 → 回答

贯穿
  评估与监控（离线评测集 + 在线 trace）
```

## 4. LangGraph 图设计（初稿）

### 4.1 State

```python
from typing import TypedDict, Annotated
from langgraph.graph.message import add_messages

class RAGState(TypedDict):
    messages: Annotated[list, add_messages]  # 多轮对话历史
    question: str                  # 原始问题
    standalone_question: str       # 指代消解后的完整问题，重排用
    queries: list[str]             # 本轮检索用的 1~3 条查询
    tried_queries: list[str]       # 之前用过的查询，改写重试时避免重复
    intent: str                    # rag / chat / clarify
    prev_intent: str | None        # 上一轮的 intent，防止连续反问
    clarify_question: str | None   # intent=clarify 时返回给用户
    filters: dict | None           # 硬过滤：接口参数传入，始终生效
    soft_filters: dict | None      # 软过滤：从问题里识别，只在首次检索生效
    use_soft: bool                 # 当前检索是否带软过滤
    scope_note: str | None         # 展示给用户的生效范围
    candidates: list[dict]         # 合并后送进重排的前 30 个
    hits: list[dict]               # 重排筛选后的 top 8
    expansions: dict[str, list[dict]]  # chunk_id -> 前后 chunk / 引导段落 / 图片等
    retrieval: dict                # top_score、degraded、各步耗时
    retry_count: int               # 改写重试次数
    context_blocks: list[dict]     # 上下文段落（ContextBlock），带引用编号和 chunk_ids
    attachments: list[dict]        # 附件图片，随回答返回给前端
    answer: str                    # 最终回答
    gen_meta: dict                 # prompt 版本、估算输入 token、裁掉的历史轮数等（引用来源由 context_blocks 得到）
```

### 4.2 节点与边

```
START → preprocess ─┬─ rag     → retrieve → rerank ─┬─ 通过 / 降级 → build_context → generate → postprocess → END
                    │                ↑              ├─ 未通过且重试 < 2 → rewrite ─┬─ 有新查询 → retrieve
                    │                └──────────────┼──────────────────────────────┘
                    │                               └─ 未通过且已重试 2 次 / 改写无新查询 → fallback → postprocess
                    ├─ chat    → generate（闲聊模式，不检索）
                    └─ clarify → clarify → postprocess → END
```

边的汇总：

| 起点 | 条件 | 终点 |
|------|------|------|
| preprocess | intent = rag / chat / clarify | retrieve / generate / clarify |
| rerank | top_score ≥ 0.4 或重排降级 | build_context |
| rerank | top_score < 0.4 且 retry_count < 2 | rewrite |
| rerank | top_score < 0.4 且 retry_count = 2 | fallback |
| rewrite | 有新查询 | retrieve |
| rewrite | 去重后没有新查询或调用失败 | fallback |

- preprocess 的意图、指代消解、查询扩展、范围识别见[用户问题预处理](用户问题预处理.md)。
- grade 是 rerank 之后的条件边，只看重排最高分，不额外调用 LLM，见[检索与重排](检索与重排.md) §7。
- rewrite：本轮用了软过滤就先去掉它，查询不变；否则调用改写 LLM 生成新查询。`retry_count + 1`，见[用户问题预处理](用户问题预处理.md) §9。
- fallback：回答“资料不足”，并列出最接近的几个来源。
- D-003 A：`StateGraph(RAGState, context_schema=Deps)`，节点和需要配置的条件路由接收 `runtime: Runtime[Deps]`；`runtime.context` 提供配置、客户端、信号量和 token 计数器，`runtime.stream_writer` 发事件。依赖不存进 State/checkpoint。SQLite checkpointer 以 `configurable.thread_id=session_id` 隔离会话。
- D-004：预处理、clarify、rewrite、rerank 节点归 L2；build_graph、Deps、fallback、API 主程序归 L3。
- 后续可扩展：工具调用节点。

### 4.3 API 与运行时组装

- 问答入口：`POST /api/chat`，JSON 含 `question`、可选 `session_id` 和 `filters`；也可用 `X-Session-ID` 提供会话。二者同时出现必须相同，缺失、空值或非法标识拒绝请求。同会话串行执行，不同会话的历史与锁隔离。
- `session_id` 仅允许 1～128 位 ASCII 字母、数字、下划线和连字符；SQLite checkpoint 使用 `configurable.thread_id=session_id`。反馈入口复用 `X-Session-ID`，仅接受本会话历史中的 `message_id`。当前没有用户鉴权，仍依赖内网部署控制访问。
- 原文：`GET /api/docs/{doc_id}/file`，按只读登记表的有效版本访问 `paths.clean/{doc_id}/v{version}/full.md`；图片：`GET /api/images/{doc_id}/v{version}/{filename}`。客户端不提供文件系统路径，路径解析后必须仍在清洗根目录内。
- `build_graph(checkpointer=None, *, nodes=None)` 默认组装正式 L2 节点；`create_app(cfg=None, *, deps=None, graph=None, graph_factory=build_graph, metrics=None, trace_client=None, feedback_store=None)` 允许注入依赖用于测试和评测，生产默认在 lifespan 中建立并关闭资源。
- 演示页：`GET /` 返回 `api/static/index.html`，`/static/*` 提供同目录的 JS/CSS/图标，与 API 同源。页面用 `fetch` 读 `POST /api/chat` 的 SSE，流式阶段只显示纯文本，收到 `final` 后按 UTF-16 偏移重绘引用（`unsupported`、`invalid_number`、`in_supplement` 标灰）和来源列表；反馈调 `POST /api/feedback`。模型输出一律转义，不插入原始 HTML；响应头带严格 CSP（只允许同源脚本、样式、图片和连接）。接口没有鉴权，演示页只在本机或可信内网打开。
- D-013 B：LLM 保留原调用签名，不追加可选监控/客户端参数。指标通过 `llm.observability.METRICS` 进程全局入口访问，Deps 的 `metrics` 仅为只读兼容属性，不是构造字段；`message_id` 从 RunnableConfig.metadata 读取，关联 final、历史和 trace，不放进 Deps。`prompt_env` 未传入时按 `prompt.dir` / `prompt.version` 构建。

## 5. 技术栈

部署方式是混合的：LLM 走 API，Embedding 和 Rerank 在本地跑。

| 层 | 选型 | 说明 |
|----|------|------|
| 编排 | LangGraph | 在线问答图 |
| 文档解析 | MinerU API（云端，可切换为自部署） | PDF/Word/PPT/图片转 Markdown + content_list.json |
| 向量库 | Milvus 2.5+（Standalone，Docker） | 稠密向量用 DISKANN 索引，需要 `queryNode.enableDisk=true`，数据盘建议 NVMe SSD；关键词检索用内置 BM25 |
| 文档登记 | SQLite（含 FTS5 标题索引） | 记录文件路径、标题、内容哈希、版本、解析状态，用于增量入库和问题中的文档范围识别 |
| 会话状态 | LangGraph checkpointer（SQLite） | 按 session_id 保存对话历史 |
| 预处理 LLM | OpenAI 兼容接口的小模型（主 + 备用） | 意图、指代消解、查询扩展、范围识别、重试改写；和生成模型分开配置 |
| Embedding | Visualized-BGE（bge-m3 底座，本地 RTX 4060，fp16） | 文本和图片编码到同一个 1024 维空间；不输出稀疏向量，由 BM25 补充 |
| Rerank | bge-reranker-v2-m3（本地 RTX 4060，fp16） | cross-encoder 重排 |
| LLM | OpenAI 兼容接口，langchain-openai 的 ChatOpenAI | 每个场景（generate / chat / preprocess / rewrite）一个主模型、一个备用模型；地址和模型名在 config.yaml，key 在环境变量 |
| API 服务 | FastAPI | 支持 SSE 流式输出 |
| 评测 | 自写出题器 + RAGAS 打分 | 快速档每次改动跑，完整档上线前跑，关键指标不达标返回非零退出码 |
| 监控 | Langfuse 云端 + Prometheus + Grafana | trace 只上报元数据；指标和告警在内网 |
| 包管理 | uv，Python 3.12 | 本机 3.14 太新，部分依赖可能没有安装包 |

## 7. 决策记录

| 问题 | 结论 |
|------|------|
| DiskANN 形态 | Milvus 的 DISKANN 索引 |
| 模型接入 | 混合：LLM 走 API，Embedding 和 Rerank 本地部署 |
| 数据源 | PDF、Word、PPT、图片、Markdown/纯文本；暂不支持 Excel |
| 文档解析 | PDF/Word/PPT/图片走 MinerU API，MD/TXT 本地解析 |
| 文档切分 | 结构优先的层级切分，target / max 双预算，见 `文档切分.md` |
| 空章节标题覆盖 | D-014：无正文的空章节标题不单独成 chunk；完整覆盖 oracle 排除这类允许丢弃的标题，其余正文按 seq 去重叠和占位符后必须逐字恢复；见 `文档切分.md` §5、§13 |
| 向量化输入 | chunk 带上自己所在的标题路径一起向量化（稠密向量和 BM25 都用 `embed_text`） |
| Embedding | Visualized-BGE（图文多模态），稀疏检索改用 Milvus BM25 |
| 上下文构造 | 预算 6k token；按文档分组、文档内按原文顺序；所在节 ≤ 1500 token 时整节放入，否则补前后 chunk；图片命中发原图（最多 2 张），附件图片只返回前端 |
| Prompt 组装 | 资料在前问题在后，标签隔离 + 只转义保留标签；句末 `[n]` 引用；资料不够时允许在固定标题下补充自身知识；生成看最近 3 轮历史（去掉旧引用）；fallback 用固定模板不调用 LLM |
| 后处理 | 不改正文；引用先做格式校验，再用本地重排模型打分做支持度校验（阈值 0.3，最多等 3 秒）；有问题的引用标灰，不支持超过一半加整体提示；来源列表只列被引用的；保存原文 + 去引用的 plain 版本；clarify 也经过后处理 |
| 评估与监控 | 评测集全部由 LLM 生成（约 500 题，标准答案记“文档 + 原文片段”）；RAGAS 打分；两档评测 + 回归门槛；Langfuse 云端（遮掉原文）+ Prometheus 告警 |
| 节点依赖注入（D-003） | LangGraph context_schema + Runtime，Deps 存配置/客户端/信号量/计数器，流事件用 runtime.stream_writer；配置与业务依赖不使用全局变量、不写 checkpoint；指标按 D-013 B 使用进程全局入口 |
| 模块归属（D-004） | L2 负责预处理/改写/clarify/rerank；L3 负责图组装/Deps/fallback/API 主程序；API 挂载 L4 反馈与指标 |
| 结构化失败（D-005） | None 当失败处理，主备各调用一次，备用仍失败按规则降级 |
| 问答 API 与会话（D-006） | POST /api/chat；body session_id 与 X-Session-ID 任选其一，同传须一致；原文按登记版本访问 clean/id/vN/full.md |
| 图片公开 URL（D-007） | GET /api/images/{doc_id}/v{version}/{filename}；API 去掉内部 image_path，输出安全 URL；文档/版本/文件名及目录边界校验 |
| 全局监控与旧签名（D-013 B） | structured_call 四参数 / stream_answer 五参数原签名不变；使用全局指标入口，测试 monkeypatch；Deps 不追加 metrics/message_id 构造字段，message_id 取 RunnableConfig.metadata |
| 大模型生成 | 统一 OpenAI 兼容接口，每个场景主 + 备用；首字前 429/5xx 重试 2 次，超时和 4xx 直接切备用，首字前总时长 30 秒；开始输出后出错不重试、标记中断；正文推原文，后处理只追加 final 事件 |
| 文档位置 | 设计文档统一放在 `docs/`，文档之间用同目录相对链接 |
| 配置 | 全部可调参数集中在根目录 `config.yaml`，各文档只说明含义；密钥只写环境变量名；Milvus 服务端参数在 `milvus.yaml`；Prompt 模板在 `prompts/{version}/` |
| 硬件与规模 | GPU 为 RTX 4060（8 GB 显存）；按 1000 万 chunk 设计，Milvus 常驻内存控制在 10 GB 以内 |
| 权限 | 不做部门、密级等权限过滤，只用 Milvus 账号鉴权 |
| 问题预处理 | 一次小模型调用输出 intent（rag / chat / clarify）、完整问题、最多 2 条扩展查询、范围；问题里识别出的范围作为软过滤，重试时先去掉 |
| 开发顺序 | 先串行做 P0（骨架、契约、夹具、桩），再按依赖关系并行四条线：L1 离线入库、L2 检索与上下文、L3 生成链、L4 评测与监控；见[开发计划](开发计划.md) |
| 检索与重排 | 混合检索用 Milvus 加权融合（稠密 0.5 / BM25 0.5，M4 校准）；重排候选 30、top 8；图片和文本一起重排；grade 只看重排分数（通过线 0.4（M4 校准），最多重试 2 次） |
| 去重策略 | 切分时给每个 chunk 算 `content_hash`（归一化 text 的 sha256）并入库；入库时只做文档内去重（重复和模板文本标 `searchable=false`），跨文档副本都保留可检索；召回后按 content_hash 去重保留最高分，避免限定文档检索时丢失内容 |
| 数据结构 | 跨模块的数据结构统一用 pydantic v2 `BaseModel`，文档里的定义和各包 `models.py` 逐字对应，构造一律用关键字参数；`RAGState` 保持 TypedDict，里面存模型 `model_dump()` 后的 dict |
| 代码切分超长行 | 优先在行边界切分；单行超过 800 token 时允许在语法边界（逗号、分号、括号）行内切分，找不到边界时按 token 硬切并标记 force_split |
| M4 评测落实（D-008～D-012） | 真实语料出题 471/500 题（缺题保留，不用夹具补）；中文 RAGAS 30 条实评后人工适配中文 prompt；七项校准只出建议，由用户审核后改配置；Langfuse 云端只上报 2 条公开合成 trace（mask）。2026-10-03 裁决：完整档 471 题双跑和补题不再跑，评测链跑通即可，基线暂未写入 |
| MinerU 云端验收（D-015、D-018） | 维持严格顺序（D-015 B）；后因任务长期 pending，L1 完成标准改为本地管线交付（D-018 B），云端解析质量、每页耗时和 20 份人工检查暂挂 |
| GPU 依赖（D-016） | torch、torchvision、transformers 等精确版本追认保留，用于本地 Visualized-BGE 与重排服务 |
| 正式集合别名（D-017、D-019） | Milvus 容器生命周期归用户；`rag_chunks` 改为别名，指向真实入库集合；原实体集合改名备份，不删数据 |
