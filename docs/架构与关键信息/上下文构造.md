# 上下文构造

## 1. 目标

把[检索与重排](检索与重排.md)交过来的命中和扩展内容，整理成交给生成模型的上下文：
- 按优先级挑选内容，总量控制在 token 预算内，放不下的整块丢弃，不从中间截断。
- 命中所在的小节不大时整节放入，节太大时补前后 chunk。
- 按文档分组，文档内按原文顺序排列，相邻 chunk 合并成连续段落。
- 每个段落分配一个引用编号，并记录它由哪些 chunk 组成，供[后处理](后处理.md)校验引用。
- 图片命中把原图交给生成模型；附件图片只返回给前端展示。

输入（来自 RAGState）：
- `hits`：最多 `rerank.top_n` 个命中，带重排分数（降级时只有融合分数）
- `expansions`：每个命中的扩展内容，按 role 区分：`lead_in` / `split_sibling` / `anchor` / `section` / `neighbor` / `attachment`

输出：
- `context_blocks`：ContextBlock 列表（§8），渲染成 Prompt 文本由 [Prompt 组装](Prompt%20组装.md) 负责
- `attachments`：附件图片列表，随回答返回给前端

所有参数都在 `config.yaml` 的 `context` 段（整节阈值在 `expansion` 段）。

## 2. 流程

```
hits + expansions
  ↓ ① 预算：budget_tokens 先扣掉每个段落的固定开销
  ↓ ② 按优先级填充（§4）：
  │    P1 命中（图片命中附原图）
  │    P2 必须的伴随内容：引导段落、相邻拆分段、图片锚点
  │    P3 整节（≤ 1500 token）；放不下就改为前后 chunk
  │    P4 附件图片：不占预算，单独返回
  ↓ ③ 合并与排序（§7）：按文档分组 → 文档内沿 prev/next 链合并 → 去掉拆分段的重叠 → 插入章节标题
  ↓ ④ 分配引用编号（§8）
  ↓ context_blocks + attachments
```

## 3. 预算

| 项 | 默认值 | 说明 |
|----|--------|------|
| `budget_tokens` | 6000 | 只算检索到的上下文，系统提示、对话历史、问题的预算在 Prompt 组装里分配 |
| `block_overhead_tokens` | 30 | 每个段落的来源行（引用编号、标题、页码）开销，按 `top_n` 个段落预先扣除 |
| `token_safety_factor` | 1.1 | chunk 的 token 数用 Milvus 里的 `tokens` 字段（bge-m3 计数），乘以该系数作为预算成本 |
| `image.tokens_per_image` | 1200 | 每张原图计入预算的 token 数 |

系数校准：bge-m3 的 tokenizer 和生成模型的切词方式不同，中文差异可能不小。上线前抽 1000 个 chunk，逐个作为唯一内容发一次最小请求（`max_tokens=1`），用返回的 `usage.prompt_tokens` 减去固定开销，和 `tokens` 字段对比，取 p95 比值作为 `token_safety_factor`（OpenAI 兼容接口一般没有单独的计数接口，见[评估与监控](评估与监控.md) §7）。

## 4. 按优先级填充

| 优先级 | 内容 | 放不下时 |
|--------|------|----------|
| P1 | 命中 chunk 正文，按重排分数从高到低；图片命中附原图（最多 2 张） | 图片放不下就只用说明文字；正文放不下就丢弃这个命中及其伴随内容 |
| P2 | 伴随内容：代码的引导段落、紧挨着的拆分段、图片命中的锚点段落 | 跳过 |
| P3 | 命中所在的整节（`section_tokens ≤ 1500`）；节太大时改为前后 chunk | 整节放不下改为前后 chunk，再放不下就跳过 |
| P4 | 附件图片 | 不占预算，单独放进 `attachments` |

```python
def fill(hits, exp, cfg):
    """返回 (chosen, roles, attachments, send_image)。"""
    budget = cfg.budget_tokens - cfg.block_overhead_tokens * cfg.top_n
    chosen: dict[str, dict] = {}   # chunk_id -> chunk
    roles: dict[str, str] = {}     # chunk_id -> hit / lead_in / section / ...
    send_image: set[str] = set()   # 需要发原图的图片 chunk_id
    used = 0

    def cost(c) -> int:
        return 0 if c["chunk_id"] in chosen else ceil(c["tokens"] * cfg.token_safety_factor)

    def take(items, role) -> bool:
        nonlocal used
        need = sum(cost(c) for c in items)
        if used + need > budget:
            return False
        for c in items:
            if c["chunk_id"] not in chosen:
                chosen[c["chunk_id"]], roles[c["chunk_id"]] = c, role
        used += need
        return True

    # P1：命中；图片命中先尝试带上原图
    kept = []
    for h in hits:
        if h["type"] == "image" and len(send_image) < cfg.image.max_images:
            if used + cost(h) + cfg.image.tokens_per_image <= budget and take([h], "hit"):
                used += cfg.image.tokens_per_image
                send_image.add(h["chunk_id"])
                kept.append(h)
                continue
        if take([h], "hit"):
            kept.append(h)
    # P2：伴随内容
    for h in kept:
        for role in ("lead_in", "split_sibling", "anchor"):
            for c in exp[h["chunk_id"]].get(role, []):
                take([c], role)
    # P3：整节，放不下改为前后 chunk
    for h in kept:
        if h["type"] == "image":
            continue
        sec = exp[h["chunk_id"]].get("section", [])
        if not (sec and take(sec, "section")):
            for c in exp[h["chunk_id"]].get("neighbor", []):
                take([c], "neighbor")
    # P4：附件图片，不占预算
    attachments = dedup_images(exp, kept, cfg.images_total)   # 取 expansion.images_total
    return chosen, roles, attachments, send_image
```

- 已经放进来的 chunk 成本为 0，所以多个命中在同一节时，这一节只算一次。
- 丢弃的命中不再补它的伴随内容，也不补整节。
- `cfg.top_n` 取 `rerank.top_n`，和检索阶段保持一致。

## 5. 整节放入

- 判断依据是切分阶段写入的 `section_idx` 和 `section_tokens`（见[文档切分](文档切分.md) §4），不需要额外查询就能知道一节有多大。
- `section_tokens ≤ expansion.section_max_tokens`（默认 1500），并且命中本身不是整节（`meta.strategy != "section"`）时，检索阶段按 `doc_id + version + section_idx` 把整节取回，role 为 `section`。
- 整节包含 `searchable=false` 的重复 chunk（它们是原文的一部分），不包含图片 chunk（图片按附件处理）。
- 小兄弟节合并成的 chunk，`section_idx` 指向父节，所以整节取的是父节。
- 节超过阈值时，检索阶段只取前后 chunk（role 为 `neighbor`）。

## 6. 图片

| 类型 | 交给生成模型的内容 | 返回给前端 |
|------|--------------------|------------|
| 图片命中（进入 `rerank.top_n`） | 原图 + 图片说明 + 锚点段落；最多 2 张，预算不够时只给说明文字 | 是 |
| 附件图片（文本命中关联的图片） | 只有正文里的占位符 `[图: 说明]` | 是，最多 4 张 |

原图处理：
- 长边缩到 1024 像素，保持宽高比，转成 RGB 后存成 JPEG（质量 85）。
- 在 Prompt 组装时再读文件、做 base64 编码，这一步只记录路径。
- `image_path` 只允许 `data/clean/` 下的相对路径（入库时已校验），读取前再检查一次，拒绝 `..` 和绝对路径。
- 文件不存在或读取失败时，降级为只用说明文字，并记日志。

## 7. 合并与排序

1. 按文档分组：文档按其中最高的重排分数从高到低排序（降级时用融合分数）。
2. 文档内按 `seq` 排序，沿 `prev_id` / `next_id` 链找连续的 chunk，连续的合并成一个段落。图片 chunk 不在链上，不参与合并。
3. 合并拆分段时去掉重叠：切分阶段在 `meta.overlap_chars` 里记录了每段开头与上一段重复的字符数，拼接时去掉这部分。
4. 段落内 `section_path` 发生变化时，插入一行标题（取变化后的最后一级，用 Markdown 标题格式），避免多个小节的内容混在一起看不出分界。
5. 图片命中：锚点 chunk 所在的段落已经在上下文里时，图片挂到这个段落上；否则图片单独成一个段落。

## 8. 引用编号与输出结构

每个合并后的段落一个编号，按最终顺序从 1 开始。

```python
from pydantic import BaseModel, Field

class ImageRef(BaseModel):
    chunk_id: str
    image_path: str
    caption: str
    send_original: bool        # True：原图交给生成模型；False：只用说明文字

class ContextBlock(BaseModel):
    cite: int                  # 引用编号 [1] [2] ...
    doc_id: str
    title: str
    section_path: str          # 段落第一个 chunk 的标题路径
    page_start: int            # 没有页码时为 -1
    page_end: int
    text: str                  # 合并、去重叠、插入标题后的 Markdown
    chunk_ids: list[str]       # 组成这个段落的全部 chunk，后处理校验引用用
    hit_ids: list[str]         # 其中哪些是命中（其余是扩展内容）
    score: float               # 段落内最高的重排分数
    images: list[ImageRef] = Field(default_factory=list)
```

- 整节放入时整节是一个段落，只有一个编号，引用粒度会比单个 chunk 粗一些。
- `citations` 不单独维护，由 `context_blocks` 直接得到（编号 → 标题、章节、页码、chunk_ids）。
- `RAGState.context_blocks` 存 `model_dump()` 之后的 dict，和 `hits` 一样（见[检索与重排](检索与重排.md) §4.5）。

## 9. 特殊情况

| 情况 | 处理 |
|------|------|
| 重排降级（没有重排分数） | 所有排序改用融合分数，其余流程不变 |
| 单个命中就超过预算 | 不可能发生：切分的 `max_tokens`（800）远小于预算；保险起见仍按“放不下就丢弃”处理，并记日志 |
| 降级模式下 `hits` 为空 | 输出空的 `context_blocks`，由生成阶段按“资料不足”模板回答 |
| intent = chat、fallback | 不经过这一步 |

## 10. LangGraph 节点

`build_context` 节点：读 `hits`、`expansions`，写 `context_blocks`、`attachments`，并把各优先级实际用掉的 token 数写进 `retrieval["context_usage"]`，供监控统计。

## 11. 验证

单元测试：
- 总成本（chunk 成本 + 图片 + 段落开销）不超过 `budget_tokens`。
- 优先级正确：预算不够时，被丢弃的只会是低优先级内容或排名靠后的命中。
- 同一个 chunk 只出现一次；同一节被多个命中引用时只放一次。
- 拆分段合并后与原文一致（重叠部分只出现一次）。
- 段落内 `section_path` 变化处有标题行。
- 文档顺序按最高分，文档内按 `seq`。
- 每个命中都在某个段落的 `hit_ids` 里（被预算丢弃的除外）。
- 原图最多 2 张，附件最多 4 张；非法 `image_path` 被拒绝。

上线前校准 `token_safety_factor`（§3）。

评测指标（放在[评估与监控](评估与监控.md)）：答案所在 chunk 进入上下文的比例、预算利用率、整节放入比例、因预算丢弃的命中数、原图发送比例。

## 13. 限制与校准

- 整节作为一个引用编号，引用粒度偏粗；如果后处理需要更细的定位，可以在段落内部再标注 chunk 级的子编号。
- `tokens_per_image` 按 1200 估算，不同服务商对图片的计费方式不同，接入生成模型后按实际情况调整。
