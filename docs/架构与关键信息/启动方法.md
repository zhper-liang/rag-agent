# 启动方法

本文是单机启动的速查手册。部署原理、systemd 单元细节、健康语义见[服务化部署](服务化部署.md)；所有端口、地址、路径以 `config.yaml` 为准。

## 1. 前置条件

- Python 3.12（由 uv 管理）、Docker、Node >= 22.12（只在构建前端时需要）、NVIDIA 驱动（编码 + 重排服务用 GPU）。
- 复制 `.env.example` 为 `.env` 并填写真实密钥（Milvus、MinIO、LLM 接入点、MinerU、Langfuse、Grafana）。`.env` 已被 gitignore，不要提交。
- 安装依赖：`uv sync`。

## 2. 启动顺序

```
Milvus（compose healthy） → 编码 + 重排服务（/health 200） → 问答 API
```

### 2.1 Milvus

```bash
docker compose -f docker-compose.milvus.yml up -d
docker compose -f docker-compose.milvus.yml ps      # 等到 healthy
```

停止：`docker compose -f docker-compose.milvus.yml down`。compose 文件没有 `restart` 策略，开机自启由你自己决定。

### 2.2 编码 + 重排服务（GPU）

```bash
uv run --env-file .env python -m ragagent.index.embed_service
```

模型加载需要几十秒，期间 `/health` 返回 503。端口见 `config.yaml` 的 `services.embed`。

```bash
curl -s http://127.0.0.1:8001/health      # 端口以 services.embed.port 为准
```

### 2.3 问答 API + 演示页

```bash
uv run --env-file .env uvicorn ragagent.api.app:create_app --factory --host 127.0.0.1 --port 8000
```

- 只能跑 1 个 worker，不要加 `--workers`。
- 没有登录鉴权，只绑 127.0.0.1；需要从别的机器访问时用 SSH 端口转发，不要改成 `0.0.0.0`。
- 打开 `http://127.0.0.1:8000/`。

## 3. 前端构建（首次部署和前端有改动时）

```bash
cd web
npm ci
npm run build        # 产物输出到 src/ragagent/api/static/，不提交
```

没有构建产物时 API 照常启动，但 `/`、`/c/*`、`/d/*` 返回 503，问答接口不受影响。前端开发调试用 `npm run dev`。

## 4. 验收

```bash
curl --fail --silent --show-error http://127.0.0.1:8000/api/health/live
curl --fail --silent --show-error http://127.0.0.1:8000/api/health/ready
uv run --env-file .env python scripts/check_health.py
```

`ready` 返回 200 才表示 Milvus、编码服务、登记表都可用；503 时看返回里的 `checks.milvus` / `embed` / `registry`。

## 5. 开机自启（systemd 用户单元，可选）

```bash
mkdir -p ~/.config/systemd/user
cp deploy/systemd/*.service deploy/systemd/*.timer ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now ragagent-embed ragagent-api ragagent-gpu
systemctl --user enable --now ragagent-backup.timer
loginctl enable-linger "$USER"
```

- 单元文件里的 `%h/code/ragagent` 和 `%h/.local/bin/uv` 按实际路径改。
- Milvus 不在 systemd 管理范围内，先手动 `docker compose up -d`。
- 看状态：`systemctl --user status ragagent-api`；看日志：`journalctl --user -u ragagent-api -f`。
- 改了代码或 `config.yaml` 后：`systemctl --user restart ragagent-api`。尽量别重启 `ragagent-embed`（重新加载模型要几十秒）。

## 6. 离线入库（有新文档时）

入库独占 `paths.ingest_lock`，拿不到锁会立即报错退出。入库会占用编码服务的 GPU，大批量放在低峰跑。

```bash
# 清洗（解析、清洗、去重、登记）
uv run --env-file .env python -m ragagent.ingest.pipeline <input_dir> [--limit N] [--local-only]

# 切分（单独调试时用）
uv run --env-file .env python -m ragagent.ingest.chunking.pipeline <input> [--output <dir>]

# 向量化并写入 Milvus（需要 Milvus 与编码服务已启动）
uv run --env-file .env python -m ragagent.index.pipeline <chunk_dir> [--force] [--no-wait]
```

也可以直接在演示页上传文档，说明见[服务化部署](服务化部署.md) §11。

## 7. 监控栈（可选）

```bash
uv run --env-file .env python scripts/gen_monitoring.py
docker compose --env-file .env -p ragagent-monitoring -f deploy/monitoring/generated/compose.yml up -d
```

需要先在 `.env` 里设置 `GRAFANA_ADMIN_PASSWORD`。Prometheus / Grafana 只发布到主机回环。

## 8. 测试与评测

```bash
make test            # 后端测试（uv run pytest）
make test-web        # 前端测试（需先 npm ci）
uv run python -m eval.run --tier quick --fixture    # 离线评测壳，不调用真实服务
```

真实评测需要 `--env-file .env`、`--chunks` 和显式的 `--max-calls`，详见 `eval/README.md`。

## 9. 常见问题

- **API 启动失败**：Milvus 没起来。API 在 lifespan 里连接 Milvus，先确认 compose 是 healthy。
- **问答提示“服务暂时不可用”**：编码服务还在加载模型或已停止，查 `curl http://127.0.0.1:8001/health`。
- **页面显示“前端未构建”**：执行第 3 节的前端构建，然后重启 API。
- **入库立即退出**：另一个入库进程持有 `paths.ingest_lock`，等它结束再跑。
