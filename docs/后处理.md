# 后处理

## 1. 目标

正文已经原样推给了前端，后处理不改正文，只做两件事：
- 生成 `final` 事件：引用校验结果、来源列表、补充说明的位置、截断或中断提示。
- 保存本轮对话：模型原文、去掉引用标记的 `plain` 版本（给后续轮次的历史用）和引用元数据。

引用校验分两层：
- 格式校验：编号是否存在、是否出现在补充说明里。
- 支持度校验：用本地重排模型给“句子-引用段落”打分，低于阈值算不支持。

输入（来自 RAGState）：`answer`、`context_blocks`、`gen_meta`、`intent`、`question`。
输出：`final` 事件；写回 `messages`（本轮问答）和 `gen_meta.post`（统计）。

参数在 `config.yaml` 的 `postprocess` 段；补充说明标题复用 `prompt.supplement_heading`。

## 2. 流程

```
answer + context_blocks + gen_meta
  ↓ status = failed：不保存、不发 final（前端已收到 error 事件），结束
  ↓ ① 解析（§3）：代码替换成等长空白 → 找补充说明标题 → 分句 → 找出 [n]
  ↓ ② 格式校验（§4）：补充说明里的引用、不存在的编号
  ↓ ③ 支持度校验（§5）：句子 × 引用段落送重排打分，最多等 3 秒
  ↓ ④ 整体提示（§6）：不支持的句子超过一半时加提示
  ↓ ⑤ 来源列表（§7）：只列被引用的段落
  ↓ ⑥ 发 final 事件（§8）
  ↓ ⑦ 保存本轮（§9）：原文 + plain + 元数据
```

不同路径的处理：

| 路径 | 引用校验 | 来源列表 | 保存 |
|------|----------|----------|------|
| rag / rag_empty | 做 | 有 | 是 |
| chat | 不做（没有资料） | 无 | 是 |
| fallback | 不做（固定模板，没有 `[n]`） | 无（最接近的来源已经写在回答正文里） | 是 |
| clarify | 不做 | 无 | 是（防止连续反问要用到这一轮） |
| 生成失败 | — | — | 否 |

## 3. 解析

### 3.1 屏蔽代码

先把代码块和行内代码替换成等长的空白，后面的查找都在屏蔽后的文本上做，位置和原文一一对应。这样代码里的 `arr[1]` 不会被当成引用，也不会被分句切开。

```python
import re
import unicodedata

CITE = re.compile(r"\[(\d{1,3})\]")
# 围栏写成 `{3,} / ~{3,}（不直接写三个反引号，避免破坏本文档的代码块）；未闭合的代码块一直屏蔽到结尾
FENCE = re.compile(r"^[ \t]*(`{3,}|~{3,}).*?(?:^[ \t]*\1[ \t]*$|\Z)", re.S | re.M)
INLINE = re.compile(r"`[^`\n]+`")

def mask_code(text: str) -> str:
    blank = lambda m: re.sub(r"[^\n]", " ", m.group(0))   # 保留换行，其余换成空格
    return INLINE.sub(blank, FENCE.sub(blank, text))
```

中断的回答可能停在代码块中间，未闭合的代码块一直屏蔽到末尾。

### 3.2 补充说明

```python
def _norm(s: str) -> str:
    s = unicodedata.normalize("NFKC", s)
    return re.sub(r"[\s*_#]", "", s)

def find_supplement(masked: str, heading: str) -> int | None:
    """返回补充说明标题所在行的起始位置；没有则返回 None。"""
    target, pos = _norm(heading), 0
    for line in masked.splitlines(keepends=True):
        if _norm(line) == target:
            return pos
        pos += len(line)
    return None
```

比较时去掉加粗、标题符号、空白和全半角差异，模型把标题写成 `### 补充说明（以下内容不来自资料）` 也能识别。标题行之后全部算补充说明。

### 3.3 分句与引用

句子在句末标点（`。！？!?；;`、英文句号后跟空白）或换行处结束；紧跟在句末标点后面的 `[n]` 仍然算前一句的引用（模型有时把引用写在标点后面）。

```python
from pydantic import BaseModel, Field

END = re.compile(r"[。！？!?；;]|\.(?=\s|$)|\n")
MD = re.compile(r"[*_#>`|]+|^\s*[-+]\s+|^\s*\d+\.\s+", re.M)

class Sentence(BaseModel):
    start: int
    end: int
    claim: str                  # 去掉 [n] 和 Markdown 符号后的句子，送去打分
    cites: list[dict] = Field(default_factory=list)   # {"n", "start", "end"}，位置是原文下标
    in_supplement: bool = False

def split_sentences(answer: str, masked: str, supp_at: int | None) -> list[Sentence]:
    out, start, i = [], 0, 0
    while i < len(masked):
        m = END.search(masked, i)
        stop = m.end() if m else len(masked)
        while (c := CITE.match(masked, stop)):         # 标点后紧跟的 [n] 归前一句
            stop = c.end()
        seg = masked[start:stop]
        cites = [{"n": int(c.group(1)), "start": start + c.start(), "end": start + c.end()}
                 for c in CITE.finditer(seg)]
        claim = MD.sub("", CITE.sub("", seg)).strip()
        if claim or cites:
            out.append(Sentence(start=start, end=stop, claim=claim, cites=cites,
                                in_supplement=supp_at is not None and start >= supp_at))
        start = i = stop
    return out
```

`claim` 从屏蔽后的文本取，代码内容已经变成空白，不参与打分。

## 4. 格式校验

每个引用一个状态：

| 状态 | 含义 | 前端 |
|------|------|------|
| `ok` | 编号存在，支持度达标 | 正常显示，可点击跳到来源 |
| `unsupported` | 编号存在，但支持度低于阈值 | 标灰，悬停提示“未能在该资料中核实” |
| `unverified` | 没做支持度校验（句子太短、超出打分上限、重排超时或不可用） | 正常显示 |
| `invalid_number` | 编号不在本轮的 `context_blocks` 里 | 标灰，悬停提示“引用编号无效” |
| `in_supplement` | 出现在补充说明里（规则要求补充部分不带引用） | 标灰，悬停提示“补充说明不应引用资料” |

```python
def check_format(sents: list[Sentence], blocks: dict[int, "ContextBlock"]) -> None:
    for s in sents:
        for c in s.cites:
            if s.in_supplement:
                c["state"] = "in_supplement"
            elif c["n"] not in blocks:
                c["state"] = "invalid_number"
            else:
                c["state"] = "unverified"      # 待支持度校验
```

## 5. 支持度校验

- 打分对象：正文里（不含补充说明）状态为 `unverified`、且 `claim` 不少于 `min_claim_chars`（8 字）的句子，和它引用的每个段落。
- 段落可能比重排模型的输入上限长（整节放入时最长约 1500 token），所以按组成段落的 chunk 切成窗口，每个窗口单独打分，取最高分。
- 一句引用多个来源时，每个编号单独打分，只要有一个 `ok`，这句就算有依据。
- 调用编码服务的 `POST /rerank/pairs`（批量“查询-段落”对，一次请求），`max_length=512`。
- 超过 `max_pairs`（默认 64）的部分不打分，保持 `unverified`。
- 整体最多等 `verify_timeout_s`（3 秒）；超时或重排服务不可用时，全部保持 `unverified`，`gen_meta.post.verify_degraded=true`，final 照常发。

```python
async def check_support(sents, blocks, chunk_texts, rerank_pairs, cfg) -> None:
    jobs = []                                # (cite, 窗口文本)
    for s in sents:
        if s.in_supplement or len(s.claim) < cfg.min_claim_chars:
            continue
        for c in s.cites:
            if c["state"] == "unverified":
                for w in windows(blocks[c["n"]], chunk_texts):
                    jobs.append((c, s.claim, w))
    jobs = jobs[: cfg.max_pairs]
    if not jobs:
        return
    try:
        scores = await asyncio.wait_for(
            rerank_pairs([(q, w) for _, q, w in jobs]), cfg.verify_timeout_s)
    except Exception:
        raise VerifyDegraded()               # 调用方记日志，所有引用保持 unverified
    best: dict[int, float] = {}
    for (c, _, _), sc in zip(jobs, scores):
        best[id(c)] = max(best.get(id(c), 0.0), sc)
        c["score"] = best[id(c)]
    for c, _, _ in jobs:
        c["state"] = "ok" if c["score"] >= cfg.support_threshold else "unsupported"
```

- `windows()`：按段落的 `chunk_ids` 取出各 chunk 的正文，逐个作为窗口；单个 chunk 超过 512 token 时再按 token 截成多段。
- `support_threshold` 默认 0.3（和检索阶段的重排阈值一致），用评测集校准（§12）。
- 已知局限：重排模型判断的是相关性，不是严格的蕴含关系，“话题相关但结论不对”的句子可能打出高分。它能拦住引用了无关资料的情况，拦不住细节写错的情况。

## 6. 整体提示

- 统计正文里带引用、且至少有一个引用做过支持度校验的句子（`ok` 或 `unsupported`）。
- 其中“没有任何 `ok`、至少一个 `unsupported`”的句子占比超过 `warn_ratio`（0.5）时，`final` 里带上提示：“部分内容未能在资料中核实，请以原文为准。”
- 只有 `unverified` 的句子不参与统计，避免重排超时时误报。

## 7. 来源列表

只列回答里被引用的段落（至少有一个引用状态不是 `invalid_number`、`in_supplement`），按编号排序：

| 字段 | 说明 |
|------|------|
| `cite` | 引用编号 |
| `title` / `section` / `pages` | 文档标题、标题路径、页码范围（没有页码时不给） |
| `doc_id` | 前端打开原文用：`GET /api/docs/{doc_id}/file` |
| `images` | 这个段落里的图片（图片命中的原图、附件图），给前端展示 |

- 原文下载接口只接受 `doc_id`（过正则校验），服务端通过登记表查出文件路径，不接受客户端传路径。
- 系统不做权限过滤，能访问问答接口的人都能打开任意来源文档。这一点和前面“不做部门、密级权限”的决定一致，部署时要确认可以接受。

- 原文下载只接受 16 位小写十六进制 `doc_id`，不接受客户端路径。只读登记表拒绝不存在或 `deleted` / `failed` / `unsupported` 文档，按登记版本访问 `paths.clean/{doc_id}/v{version}/full.md`；解析符号链接后若越过清洗根目录或文件不存在则拒绝。
- 图片入口为 `GET /api/images/{doc_id}/v{version}/{filename}`；文档必须有效，版本为正整数且不超过登记版本。文件名必须为单一文件名，禁止斜杠、反斜杠、空字节和路径跳转，只允许 PNG、JPG/JPEG、GIF、WEBP 常见位图扩展名（不区分大小写）。解析后的文件必须位于清洗根目录内，响应加 `X-Content-Type-Options: nosniff`。
- `ImageRef` 内部契约不变：图内仍使用 `image_path`。仅 API 序列化 `meta.attachments` / `final.sources[].images` 时删除该字段并增加 `url`；不合法的内部路径映射为 `null`，不暴露文件系统路径。

## 8. final 事件

```json
{
  "type": "final",
  "message_id": "b7f3…",
  "status": "ok",
  "notice": null,
  "supplement": {"start": 312},
  "citations": [
    {"n": 1, "start": 45, "end": 48, "state": "ok", "score": 0.82},
    {"n": 3, "start": 101, "end": 104, "state": "unsupported", "score": 0.12},
    {"n": 7, "start": 150, "end": 153, "state": "invalid_number"}
  ],
  "sources": [
    {"cite": 1, "title": "部署手册", "section": "第2章 部署 > 2.3 配置", "pages": "12-13",
     "doc_id": "0123456789abcdef", "images": []}
  ]
}
```

- `start` / `end` 是 `[n]` 在正文里的位置，按 UTF-16 编码单元计算，和前端 JavaScript 的字符串下标一致（中文、emoji 都不会错位）。
- `notice`：整体提示（§6），以及 `status` 为 `truncated` / `interrupted` 时的“回答过长已截断”“回答中断，内容可能不完整”，多条用换行拼接。
- `supplement.start`：补充说明标题的位置，前端据此给补充部分换样式；没有补充说明时为 `null`。
- `message_id`：前端的点赞点踩反馈用它关联到这一轮（见[评估与监控](评估与监控.md)）。

## 9. 保存本轮与 plain 版本

`plain` 给后续轮次的对话历史用（见 [Prompt 组装](Prompt%20组装.md) §7），用解析时找到的真实引用位置去掉 `[n]`，不用正则盲删，代码里的 `arr[1]` 不受影响：

```python
def make_plain(answer: str, sents: list[Sentence], status: str, cfg) -> str:
    spans = sorted((c["start"], c["end"]) for s in sents for c in s.cites)
    out, pos = [], 0
    for a, b in spans:
        out.append(answer[pos:a])
        pos = b
    out.append(answer[pos:])
    plain = "".join(out)
    if status in ("truncated", "interrupted"):
        plain += cfg.incomplete_suffix       # “（回答不完整）”
    return plain
```

- 所有引用标记都去掉（包括无效的），补充说明段保留。
- 本轮以一对消息写回 `messages`（由 checkpointer 按 session 保存）：

```python
HumanMessage(content=state["question"])
AIMessage(content=answer, additional_kwargs={
    "plain": plain, "message_id": mid, "intent": state["intent"],
    "status": status, "cites": [c for s in sents for c in s.cites]})
```

- 生成失败（`status=failed`）不写回，下一轮的历史里不会出现空回答。
- fallback 和 clarify 的 `plain` 就是回答原文。

## 10. LangGraph 中的位置

- 所有会产生回答的路径最后都进入 `postprocess`：generate（rag / rag_empty / chat）、fallback、clarify，然后到 END。
- 因此 clarify 的边从 `clarify → END` 改为 `clarify → postprocess → END`（已同步到[总揽](总揽.md)和[用户问题预处理](用户问题预处理.md)）。
- 节点按 D-003 A 接收 `(state, runtime: Runtime[Deps])`，依赖取 `runtime.context`，通过 `runtime.stream_writer` 发 `final` 事件，统计写进 `gen_meta.post`：引用数、各状态数量、覆盖率（正文里带引用的句子占比）、是否触发整体提示、`verify_degraded`、校验耗时。

## 11. 前端渲染要求

- Markdown 渲染必须关闭原始 HTML（或做净化）。后处理不改正文，模型把资料里的 HTML 原样写进回答时，只能靠前端拦住。
- `[n]` 按 `citations` 的位置渲染成可点击的角标；`unsupported`、`invalid_number`、`in_supplement` 标灰并显示悬停说明。
- 流式阶段先按普通文本显示 `[n]`，收到 `final` 后再按状态重新渲染。
- `supplement.start` 之后的内容换一种样式（例如浅色背景），提示用户这部分不来自资料。
- `notice` 显示在回答下方。

## 12. 验证

单元测试：
- 代码块和行内代码里的 `[1]` 不算引用；未闭合的代码块一直屏蔽到结尾。
- 标题写成 `**补充说明（以下内容不来自资料）**`、`### 补充说明(以下内容不来自资料)` 都能识别；补充说明里的 `[n]` 标为 `in_supplement`。
- `句子。[1]` 和 `句子[1]。` 都把 `[1]` 算作这一句的引用。
- 不存在的编号标为 `invalid_number`。
- 重排超时：全部保持 `unverified`，不触发整体提示，final 照常发。
- `plain` 去掉了所有引用标记，代码原样保留；截断时末尾有提示。
- 位置按 UTF-16 计算：正文里有 emoji 时 `start` / `end` 仍然正确。

阈值校准（放在[评估与监控](评估与监控.md) §7）：用完整档评测生成的回答，由评测模型逐条判断“句子-引用”是否真的被支持，作为标签，看不同 `support_threshold` 下的误报和漏报，选定阈值。

## 14. 待讨论

- 重排模型只能判断相关性，细节写错的句子拦不住；如果评测显示伪造引用多，再考虑对 `unsupported` 或低分句子加一轮小模型判断。
- 来源列表只列被引用的段落，没被引用但放进了上下文的资料用户看不到；如果用户反馈想看更多，可以加一个折叠的“其他参考资料”。
