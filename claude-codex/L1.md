## 3. 先做难点

按这个顺序做。前一步不过，不进下一步。

1. **切分（文档切分 §5~§11）是本线最难的部分**，先做。目标是 §13 列出的六条性质全部成立：
   - `tokens ≤ max_tokens`
   - 按 seq 拼回去（去掉重叠和占位符）等于原文
   - 不跨 Unit 边界（递归拆分除外）
   - 代码 chunk 是合法的围栏代码块
   - 图片锚点双向一致
   - 重复运行输出完全一致

   用 hypothesis 做属性测试（文档明确建议）。它要加 dev 依赖，按协议 §6 的依赖流程做。先写性质测试再写实现，性质测试必须先红过一次。
2. **登记表 `registry_db.py`**（数据清洗 §12 + 用户问题预处理 §8.2 的 `doc_titles`）。它是给 L2 和 L3 的第一批接口，做完立刻发「交付」，写明表结构和查询函数签名。
3. **tokenizer**（文档切分 §15）：bge-m3 计数，带缓存。L3 要用它做预算估算，做完发「交付」。
4. **M1a**（开发计划 §6）：用 `tests/stubs/embed_server` 的假向量，把 `tests/fixtures/blocks.json` 或自己造的样例走完切分 → 编码 → `writer.index_document` → 建 DISKANN 索引 → hybrid search 出结果。collection 用 `l1_` 前缀。
5. 清洗的其余部分：router、本地 md/txt 解析、清洗规则、图片过滤、质量过滤、去重。`convert.py` 先用按数据清洗 §7 手写的 content_list.json 测，MinerU 云端调用等 D-001。
6. **真实编码服务** `embed_service.py`：协议和桩完全一样（向量化建库 §4.2），默认端口 `services.embed.port`，挂上重排路由。要下载权重（README §9），GPU 只有你能用。
7. **M1b**：小数据集（100 份文档量级）清洗 → 切分 → 编码 → 入库，登记表状态正确，按向量化建库 §10 的表逐项验证。

## 4. 数据源

- **本地解析可以马上做**：`真实内容按量读取/` 下有 221 个 md 文件，走 md 解析器，不上传、不提交。M1b 的 100 份文档从这里抽。用 `--limit` 之类的参数控制数量，不要一次全部读进上下文。
- **MinerU 云端**（pdf、docx、pptx、图片）：要等 D-001 批准。没批之前把 client 写好，用 httpx 的 MockTransport 测协议，不调真实接口。

## 6. 已知风险

- **GPU 显存**：8 GB 要同时放下 Visualized-BGE 和 reranker（向量化建库 §6.5）。上线前先实测显存峰值，写进 `状态.md`。
- **mmap**：`localStorage.path` 已经挪到 named volume（向量化建库 §6.4），不要改回 bind mount。
- **索引异步构建**：建索引后要等 `indexed_rows` 等于总行数再 load，否则检索走的是暴力搜索。`scripts/milvus_smoke.py` 的 `wait_indexed` 有现成做法。
- `create_collection` 带 `index_params` 时会自动 load；要改索引属性，先 release。
- 不要 drop 或 release 别的线的 collection，也不要跑 `scripts/milvus_bench.py`。
